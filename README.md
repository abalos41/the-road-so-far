# The-Road-So-Far-FM
The Road So Far FM is a Supernatural-inspired music mod for Project Zomboid Build 42. It adds a custom radio station at 99.6 MHz for compatible radios and vehicles, plus Dean's Top 13 Zepp Traxx, a playable cassette with 13 sequential tracks. 

The cassette displays each track title during playback. Radio and cassette sounds can attract zombies according to device volume and the mod's Sandbox setting, which can disable this attraction. Portable devices with headphones on never attract zombies, as in the base game.

## Music volume

The Sandbox option **Music volume (%)** (`VolumePercent`, 0-100, default 100) scales the volume of all the mod's music, radios and cassettes, on top of each device's own volume slider. Being a Sandbox option it is set per world or per server.

In multiplayer every sound is played locally on each client (`playSoundImpl(name, false, nil)`; the two-argument form with `nil` is ambiguous and throws). The plain `playSound` would also send the sound to every other nearby client, where it could not be stopped or follow the device volume.

Designed with multiplayer support in mind.

Optional User Tracks support is available at 100.2 MHz when a playlist has been generated.

## Multiplayer zombie noise

In multiplayer the server decides the noise of fixed and vehicle devices. Clients only report which device is playing near them; the server finds that device itself, checks it is on, tuned to the station (or playing the cassette) and that the reporting player is close, and takes volume and range from its own device data. Each device has a single server-side counter, so the 4-8 s cadence does not depend on how many players are nearby. Reports are rate-limited per player, and a device stops emitting about 20 s after the last report. Settings are in `media\lua\shared\TheRoadSoFarFM\Noise\Noise.lua`; `[TheRoadSoFarFM][Noise]` lines in the server log show when noise starts and why a report was ignored. Portable devices still emit from the client, like the base game. Singleplayer is unchanged.

## Multiplayer late-join synchronisation

Multiplayer only; singleplayer behaves exactly as before. The server keeps a clock for the station and for every playing cassette, so everyone who can hear a source hears the same track at the same time:

- Nobody else is listening: the station moves on to the next track and the newcomer hears it from the beginning. For a cassette the same track simply starts again from its beginning (like stop and play), it is never skipped.
- The track started less than 5 s ago: the newcomer simply starts it.
- Pressing play on a cassette plays the inserting sound first for everybody near, and the track starts right after it, in step with the server clock.
- Others are listening nearby: the newcomer hears a random tuning sound (`radio-`), then a random edit (`edit-`), and so on alternately; every sound of each group plays once before any repeats. When the next track is about to begin, the shortest tuning sound plays so that it ends exactly as the next track starts for everybody at once. Radio sounds live in `42\media\sound\Radio\Extra\Multiplayer`.
- Cassettes: a late joiner hears the current track from its start (out of step with the others). A few seconds before the others' track ends it fades out, and the `rewind` sound plays so that it ends exactly as the next track begins for everybody at once. `Sync\Config.lua` has `OffsetFadeMs` (fade length).
- Others are listening far away: the newcomer plays the track from the start and is realigned when the next track begins. If they walk away, that out-of-step playback is dropped and re-decided on return.

A playback that began in step with the server (start of a track) keeps running muted while you are out of range, so walking away and coming back never restarts it. A client hears a station through a single source, however many radios are tuned to it: that one playback follows the player to whichever radio sounds louder (portable radios included), the other radios stay silent, and when the radio carrying it is switched off or retuned the playback passes to another radio of the station instead of stopping and asking the server again. When a portable radio is dropped, picked up or placed, the game hands the client a new device object; the playback of the same cassette (same device id) moves to it without restarting or asking the server. A device that loads mid-track does not start anything until it is audible or the next track begins.

Sounds can only be started from the beginning, so a late joiner cannot enter mid-song; this is the closest in-game equivalent. Track lengths come from `media\lua\shared\TheRoadSoFarFM\Sync\Durations.lua`, generated by `42\tools\Update-SoundDurations.bat` (re-run it after adding or replacing any audio). Timing and distance settings live in `Sync\Config.lua`, and `[TheRoadSoFarFM][MP][Sync]` lines in `console.txt` log every decision.
